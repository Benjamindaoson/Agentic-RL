# 奖励设计与 Reward Hacking 防护

## 核心奖励

最终任务成功由 **执行结果等价** 定义，而不是 SQL 字符串相似度：

```text
模型 SQL → 真实数据库执行 → 与 Gold SQL 执行结果比较
```

这允许不同但语义等价的 SQL 获得正确奖励。

## 奖励组成

```text
执行结果正确      +0.90
SQL 可解析         +0.03
SQL 可执行         +0.07
危险 SQL           -1.00
无效 SQL           -0.20
执行超时           -0.15
每次额外重试       -0.02
```

设计约束：只有执行结果正确的轨迹才能获得 0.5 以上奖励。模型无法通过“写出合法 SQL”“返回更多行”“反复重试”获得高奖励。

## 防护措施

- 写操作和 DDL 在执行前阻断；
- 数据库强制只读；
- 多语句查询禁止；
- 截断结果不计为匹配；
- Gold SQL 执行失败的任务直接拒绝；
- 无 ORDER BY 时按多重集合比较，有 ORDER BY 时保留顺序；
- 记录无效查询率、危险查询率、平均轮次和延迟，避免只优化最终 Accuracy。
